## 0. Коротко

- **МНЕНИЕ ИГРОКОВ** (владелец): «В игре почти нечем заниматься»; профессии одинаковые; в коридорах слишком людно для хоррора.
- **ФАКТ** (прогон 450 игровых минут ≈ 15 реальных, «идеальный» игрок мгновенно выполняет каждый шаг, seed 3): без задачи
  охранник — 79 % смены, техник — 89 %, класс D — 80 %. У учёного 29 из 37 заданий — один и тот же сеанс счёта (ошибка B1).
  Ни в одном задании этих профессий нет решения игрока: шаг — это «дойти и удерживать ИСПОЛЬЗ.», «постоять N минут»,
  «посмотреть N камер», «поговорить» или «открыть вкладку терминала».
- **ПРЕДПОЛОЖЕНИЕ**: систем в игре много и они хорошие (доступ и карты, толпа и очереди у дверей, неисправности и питание,
  медицина, оружие и ROE, разум SCP, расследования). Скучно потому, что игроку выдают те же задания-заполнители, что и NPC:
  редко (не чаще раза в 25 мин) и без развилок. Ситуации, которые симуляция уже порождает (сбой считывателя, потерянная карта,
  отказ D, звонок LF-123, ложный вызов LF-135, всплеск датчиков), до игрока почти не доходят как работа с выбором.
- **Топ-3 к реализации** (по соотношению ценности и стоимости с учётом зависимостей, §8):
  1. **КПП «Пропуск»** — охранник проверяет людей на контрольно-пропускных дверях. Сюда же входят «Стоять, документы!» и событие «Чужая карта».
  2. **«Наряд» — Директор задач v2.** Расширяет `S.TaskDirector`: ситуации берутся из состояния мира и доставляются по рации,
     через терминал, от начальника или от сотрудника лично. Шаги задания становятся действиями с исходами «успех / частично / провал»; появляются предметы.
  3. **«Ремонт»** — у техника цепочка «диагностика → инструмент со склада → ремонт → проверка» с простыми мини-механиками
     для телефона и сопровождением охраны в опасной зоне.
  - Следом (M2): **«Протокол испытания»** (учёный) и **«Барак»** (класс D). Первый играбельный результат для владельца — M1 + M2.
- **Сначала** исправить блокеры B1–B7 (§1.5): по оценке это около половины дня.

## 1. Аудит

### 1.1 Как проверялось

**ФАКТ.** Headless-скрипты на node грузят те же модули, что и `Web/tests/sim-test.js`, в том же порядке, включая `director`:
- «Смена с идеальным игроком»: старт 08:40, 450 игровых мин, seed 3. Каждый тик игрок переносится в комнату текущего шага
  и выполняет `need`: hold → `playerStepDone`, `cams:N` → `viewedCamera`, `observe` → `w.observe`, `talk/escort` → `w.talk`,
  `terminal:*` → `playerTerminal`, `experiment` → `playerExperiment`. Шаг `stay:N` засчитывается сам, пока игрок в комнате.
  Перенос игрока здесь — инструмент наблюдения, а не механика. Он завышает занятость: реальному игроку ещё нужно идти.
- «Сутки NPC»: seed 5, 24 игровых часа. Считается, какие задания по каким профессиям завершены (табло или рутина) и какие события были.
- Сэмплер толпы: каждые 30 игровых минут — сколько людей в коридорах и тоннелях и почему.
  Трафик дверей — через обёртку над `presentCard`: журнал `accessLog` ограничен 600 записями и переполняется к 12:00.
- Проверка SCP-L-001: учёный-игрок в четырёх режимах: «стоит у окна», «стоит и считает», «бездействует», а для сравнения — игрок-охранник.

### 1.2 Как задания доходят до игрока сейчас (ФАКТ)

- `SCPLife.playerDuties()` (scplife.js:880) срабатывает раз в 6 игровых минут. Если у игрока меньше двух активных задач
  и с прошлой выдачи прошло не меньше 25 минут, он выдаёт `Jobs.routine()` — ту же рутину, что и NPC этой профессии.
  Класс D получает только `labor` (75 %) или `d_chore` с 8 до 17 часов (scplife.js:889).
- `SCPLife.assign()` (scplife.js:132) отдаёт событийную задачу игроку с вероятностью 0,6, если совпала профессия.
  Временный допуск при этом получает только NPC (scplife.js:98) — см. B2.
- Виды шагов (`need`): hold / `stay:N` / `cams:N` / `observe:ID` / `talk:ID` / `escort:ID` / `terminal:TAB` / `experiment` / `interview:ID`.
  Удержание длится 1,2–5 с (game.js:216). Все шаги проверяются функциями `world.js` — `playerStepDone`, `stepAtPoi`, `tickPlayer`.
- **Директор задач v1** (`director.js`, новый) вешает на задачу метаданные: источник, общую причину («распоряжение начальства»),
  инициатора, допуск, приоритет, инструменты (текстом), условия успеха и провала, осложнения (текстом), канал и журнал;
  у части видов есть последствия (`consequence`). Форму заданий и частоту выдачи он не меняет. Канал — только подпись,
  настоящей доставки нет: у инженерного «Обхода щитков» стоит «от начальника смены».
- Уже есть готовые каналы. Строка с `e.radio` рисуется в ленте голубым со звуком рации (game.js, `processNotifications`).
  `Talk.open` показывает кнопки действий. Терминал имеет вкладки по профессии (`tabsFor`).

### 1.3 Что умеет каждая профессия

#### Охранник (guard)
- **Действия игрока (ФАКТ):**
  - дежурство `post_duty` — 10 минут постоять в комнате поста;
  - обход `patrol` — 4 точки `PatrolPoint`, удержание у каждой;
  - `camera_check` — посмотреть 4 камеры в терминале;
  - `investigate` — удержание в комнате, после чего приходит автоответ «на месте: …, посторонних нет» (scplife.js:223);
  - диалог «Конвоировать за мной» с любым D (game.js:376) — без задания и без последствий;
  - оружие, предупреждения и ROE (arms.js), протокол счёта (C).
- **Что реально меняет мир:**
  - `investigate` по молчащей рации заряжает рацию и закрывает ложную тревогу;
  - `detain` и `escort_d` работают у NPC;
  - стрельба меняет мир через медицинскую модель.
- **Сделано наполовину:**
  - Конвой игроком: D идёт за игроком (`escortOf('player')`), но шаг «доставить» для игрока — простое удержание.
    Испытание (`dTestHappened`) засчитывается только у NPC в `brain.tickJob`.
  - Проверка сообщения всегда заканчивается «никого», игроку нечего выяснять.
  - Ответ на бунт D (предупреждение → сдача → задержание, arms.js) готов, но причины бунта в симуляции нет.
    `hostileUntil` ставят только тесты (arms-test.js:54,59).
  - Нет действия «проверить пропуск» у человека. При этом карты, аннулирование, временный допуск и потери карт есть,
    а `access_audit` ловит чужие карты самого игрока.
- **Без игрока (ФАКТ, сутки, seed 5):**
  - 100 дежурств, 52 обхода, 48 проверок камер, 10 проверок сообщений — всё «дойти и постоять»;
  - конвоиры: 39 дежурств и **0 конвоев** на испытание;
  - испытаний с участием D за сутки — **1**.

#### Учёный (scientist)
- **Действия игрока (ФАКТ):**
  - наблюдение через окно или камеру: текст пишется в журнал и `obsNotes`;
  - беседа через интерком (языковая модель или локальный ответ);
  - заявка на эксперимент в терминале — выбор из `def.exps`;
  - кнопка «ПРОВЕСТИ» в наблюдательном пункте;
  - отчёт: отметить до 6 наблюдений, качество = 0,15 × число отметок, не больше 0,55 (game.js:793);
  - сеанс счёта L-001.
- **Что реально меняет мир:** `runExperiment` раскрывает свойства (`reveal`), обновляет правила содержания и поднимает `knowledge`.
- **Сделано наполовину:**
  - **B1**: сеанс игрока не засчитывается.
  - Эксперимент не ждёт, пока доставят D. `experiment.done` вызывает `runExperiment(ctx.dclass)` и не проверяет, где D
    (jobs.js:114). Конвой выдаётся отдельно (scplife.js:414) — это B7.
  - Нет гипотезы, оборудования, наблюдения во время опыта. Результат эксперимента — готовый текст.
  - Единственный выбор игрока — пункты меню терминала.
- **Без игрока (ФАКТ):** NPC сами наблюдают (≈150 раз в сутки), пишут отчёты (≈110), подают заявки (раз в 30 минут),
  проводят ≈9 экспериментов в сутки, и свойства объектов открываются.

#### Класс D (dclass)
- **Действия игрока (ФАКТ):** `labor` — 8 минут у верстака в `dhall`; `d_chore` — 2 удержания; разговоры, сон, еда.
  Предметов нет, отношения с соседями на игру не влияют.
- **Что реально меняет мир:** только `rep.dclass` растёт на +2 или +3.
- **Сделано наполовину:**
  - **B5**: игрока-D не берут на испытания.
  - У NPC есть отношения, страхи (`n.fears[scp]`), `compliance`, горе (`griefUntil`, medical.js:131), отказы
    (`refuses`, повестка `d_refusal`). У игрока-D к этому доступа нет.
  - Бунт и побег — только реакция без причины.
  - Не используются комнаты `dshower`, `d3shower`, а также `d3test`, `d3test2`, `testLock3`, `testLock4`.
- **Без игрока (ФАКТ, сутки):** 0 ссор с участием D, 23 разговора D, 1 испытание.

#### Техник (technician)
- **Действия игрока (ФАКТ):**
  - `maintenance_round` — 4 щитка по 4 с; находит скрытые неисправности сектора с вероятностью 0,6 (`infra.inspect`);
  - `repair` — одно удержание в комнате неисправности;
  - `calibrate_sensors` — удержание у пульта;
  - `power_check`.
- **Что реально меняет мир:** `infra.fix` возвращает камеру, считыватель, экран LF-135 и генератор; калибровка чинит датчик;
  обход обнаруживает неисправности.
- **Сделано наполовину:**
  - У неисправности нет причины, симптомов, диагностики, инструментов, ошибок и проверки. Все 10 видов чинятся одинаково.
  - **B2**: игроку не дают временного допуска, поэтому техника отправляют чинить камеру в камере содержания на уровне −9,
    куда он не войдёт. В прогоне перенесённого авто-игрока оператор камер ещё и сделал замечание «нахождение без допуска».
  - **B4**: ломаются камеры в пустых камерах LF-147…158.
  - Страх и запрос сопровождения есть только у NPC (brain.js:286, `requestEscort`). Пример — сюжетный техник Гуров.
- **Без игрока (ФАКТ):** у техников ≈37 обходов и 9 ремонтов в сутки; у электриков 102 «проверки генератора» в сутки.

#### Коротко про остальные (ФАКТ)
- **Медик:** у NPC глубокая модель (`medical.js`: первая помощь, транспорт, операции, морг). У игрока — «Обследовать»
  и «Беседа психиатра» в диалоге, а `treat` — это 10 минут постоять.
- **МОГ:** `standby` — постоять 10 минут, `mtf_drill` — 2 удержания. Операции МОГ (arms.js) проводят только NPC.
- **Диспетчер:** `dispatch_calls` — открыть вкладку. Итог — строка «вызовов обработано: N» (scplife.js `dispatchShift`).
- **Руководители:** повестка, бюджет, этика и утверждение заявок — это настоящие решения. Сейчас это лучшие циклы игры.

### 1.8 Вывод

**ПРЕДПОЛОЖЕНИЕ.** Профессии кажутся одинаковыми, потому что у них один глагол: «дойти и удерживать». Чтобы профессии различались,
им нужны **свои глаголы с решениями**:
- охранник сверяет человека с документом;
- техник ставит диагноз и выбирает деталь;
- учёный строит гипотезу и ловит момент наблюдения;
- класс D торгуется, подчиняется или сопротивляется.

Нужен и **поток ситуаций из живого мира** вместо заполнителя.

## 2. Принципы решения

1. **Ситуация вместо заполнителя.** Задание рождается из состояния мира: неисправность, человек у двери, сигнал датчика, отказ D.
   Заполнитель — только если ничего не происходит, и даже он содержит проверку на происшествие.
2. **В каждом задании есть хотя бы одно решение** с исходом «успех / частично / провал». Мир меняется в каждом исходе.
3. **Физические глаголы.** Посмотреть человеку в лицо, взять деталь с полки, выбрать автомат в щитке, поймать момент у окна,
   стоять рядом с конвоиром. Только читать текст — не механика.
4. **Одни и те же задания у игрока и NPC** (философия `jobs.js`). NPC выполняют шаги-действия сами, с ошибками по навыку.
   Мир живёт и без игрока, а ошибки NPC порождают работу для игрока.
5. **Жанр.** Опасность редкая, но настоящая. Большинство ситуаций заканчивается спокойно, но с неуверенностью:
   «ничего не нашли», «пропустил, а был ли пропуск настоящим?», «неисправность вернулась ночью».
   Ориентир для охранника за 15 реальных минут: 6–10 ситуаций, из них одна странная и в среднем не больше 0,1 силового эпизода.
6. **Без больших всплывающих окон.** Задание приходит строкой рации, репликой человека рядом, позицией в терминале или в наряде у начальника.
   Решения принимаются в нижней панели на половину экрана, игра в это время не останавливается.

## 6. Многоэтапные события с разными исходами

**EV-1 «Чужая карта»** (охрана; КПП). Хранится в `w.td.ev` и в существующей системе дел `life.openCase`.
1. Карта теряется:
   - уборщик находит её на полу — `Dirt.remove` (infra.js) отдаёт найденную карту NPC;
   - или NPC «теряет» карту в казарме при общих койках;
   - или две карты путаются на тумбочке.
2. На КПП человек предъявляет карту, а фото и имя не совпадают.
3. Ветки:
   - (а) **честная путаница**: двое соседей по койке. Карты меняют местами, обоим +отношения, в журнал пишется запись;
   - (б) **кража**: сотрудник с 2+ замечаниями и стрессом выше 60 идёт с найденной картой L3 в `armory` за пистолетом «для себя»
     после гибели коллеги (`griefUntil`). Если охрана пропустит, то у `arms.armory.pistol` недостача −1, оружейник найдёт её при
     `access_audit`, откроется дело, затем поиск и задержание. Если поймают на КПП, будет задержание и разговор с психиатром;
   - (в) **аномалия**: это карта «Ветрова» (LF-121). Изъятие даёт улику по делу LF-121; пропуск — `ins`+2 и новые записи `fakeAccess`.
4. Исходы видны в журнале доступа, в деле, в оружейной и в отношениях.

**EV-2 «Отказ испытуемого»** (D, охрана, учёный, этика).
1. Вызов на испытание.
2. Отказ (`refuses`, brain.js:429). Если D — игрок, отказ — это его выбор.
3. Решение конвоира: уговорить (зависит от отношений и черт D), надавить (`compliance` −0,2, недовольство блока +10) или доложить.
4. Комитет по этике (`d_refusal`, уже есть): заменить испытуемого (другой D получает стресс), отложить (репутация учёного −),
   провести принудительно (страх и недовольство растут, шаг к EV-5).
5. Испытание: раскрытие свойства, ничего, или травма.

**EV-3 «Тёмный сектор»** (техник, охрана, учёный).
1. `gens.genMain.fault` → резервный генератор под нагрузкой 1,0, питание ограничено (infra.js).
2. Техник на `genC` вручную распределяет приоритетные цепи — M1 с ограничением мощности: можно питать 3 цепи из 5.
3. Выбор, что оставить без света:
   - камеру L-001 (`chamber`) — «темнота резко повышает возбуждение» (`dark_agitates`);
   - блок D — паника и стресс;
   - лаборатории — сорванные эксперименты.
4. Охрана сопровождает учёного на сеанс счёта в тёмном коридоре.
5. Исходы: быстро восстановили — спокойно. L-001 у двери — оранжевый уровень. Ошибка в цепях — прорыв (редко).

**EV-4 «Голос в рации»** (охрана, диспетчер, техник, учёный).
1. Экран LF-135 ослаб.
2. Ложные вызовы от имени коллег (cognitive.js).
3. Охранник приходит — никого. Если доложить несоответствие, откроется дело `radio`.
4. Чтобы найти причину: диспетчер сверяет радиожурнал, учёный проводит опыт `direction`, техник калибрует экран.
5. Исходы:
   - источник найден — раскрыто `source_located`, в радиожурнале виден пеленг;
   - охрана продолжает гоняться за вызовами: усталость, а настоящий вызов потом игнорируют.

**EV-5 «Недовольство D-2»** (класс D, охрана, этика) — M2.
1. Недовольство блока: `w.td.block.dhall.discontent`, 0–100.
   - Растёт от принудительных испытаний, гибели (горе), травм, массовых наказаний, нехватки еды.
   - Падает от беседы инспектора (`d_interview`), удовлетворённых отказов, привилегий.
2. Пороги:
   - 40 — ропот и медленнее работа;
   - 60 — петиция (NPC-D несёт её к `postD`, появляется пункт повестки);
   - 75 — сидячая забастовка (D отказываются от труда и еды);
   - 90 плюс повод — бунт (3–6 D получают `hostileUntil`, отвечает arms.js: предупреждение → шокер → задержание)
     или побег через дверь с `readerFault`.
3. Исходы:
   - договорились: недовольство −30;
   - подавили: −20 сейчас, +10 потом, страх;
   - побег: розыск. Пойман, или — редко — погиб у SCP.
4. Игрок-D выбирает: вести петицию, примкнуть к забастовке, донести или остаться в стороне.

**EV-6 «Возвращающаяся неисправность»** (техник, охрана, расследование).
1. Ремонт с неверным диагнозом снимает симптомы, но ставит `relapseAt`.
2. Повторный отказ ночью → новая заявка с историей.
3. После второго повтора открывается дело. Возможные причины:
   - неверный диагноз — замечание виновнику;
   - резонанс LF-130 с генератором — уже есть история `sensor_chain`;
   - редко — порча обиженным сотрудником, которую видно по журналу считывателя щитовой.

Уже есть и подключаются к Наряду: поступление LF-159 (`arrivalTick`), психологический инцидент (`psychIncident`),
история Ветрова (`storyTick`).

## 7. Идеи (20): пять ответов и оценки

М — влияние на мобильную производительность (5 = незаметно). Ценность В = И+С+П. Индекс = В × (Ц+М) / 10.

### 10.3 Выбор и темп выдачи (игроку)

Директор работает в `TD.tick(w, dt)` раз в 2 реальные секунды, то есть раз в игровую минуту.
- Игрок не на смене, мёртв или спит: проходят только задания с приоритетом 5, по рации.
- Нагрузка = активные задачи + принятые предложения. При нагрузке 2 и больше новых приказов нет.
  Просьбы ещё могут прийти как предложения, но не больше одного ждущего.
- Кандидаты: ситуации, где `roles` включает профессию игрока, `test(w)` не пустой и нет перезарядки.
  - Оценка = вес × срочность (приоритет) × 0,3, если такой вид уже выдавали подряд, × 1/(1 + roomDistance/6).
- После выполнения — пауза 3 игровые минуты. Не больше одного приказа по рации за 5 игровых минут, если приоритет ниже 4.
- Если в мире ничего не происходит — заполнитель профессии со встроенной проверкой на происшествие:
  обход с находкой, обход щитков с замером, труд с нормой.
- **Цели (KPI)** для идеального игрока за 450 игровых минут:
  - без задачи — не больше 35 % (сейчас 79–89 %);
  - не меньше 4 разных видов заданий;
  - не меньше половины заданий содержат шаг `act:` с решением.

`SCPLife.assign()` для игрока продолжает работать. Задача проходит через `TD.route(w, t, ctx)`: канал, причина и отправитель берутся из записи решения.
`SCPLife.playerDuties()` в начале проверяет `if (S.TaskDirector && S.TaskDirector.drives(w)) return;`.

### 10.4 Доставка без больших всплывающих окон

- **Рация.** `TD.radio(w, from, text)` делает три вещи:
  - `w.notify.push({ time, type: EV.Radio, radio: true, text: name + ': «' + text + '»' })` — голубая строка со звуком рации, уже есть;
  - `w.infra.radioLog({ t, from, to: 'player', text })` — строка в КПК → РАЦИЯ → «ЭФИР»;
  - реплика отправителя, если его видно.
- **Начальник смены.** В начале смены `TD.briefing(w)` собирает наряд: 1–2 плановых блока (например, «07:10–08:10 КПП «Восток»»,
  «08:30 обход Б») и открытые вопросы из реального состояния («считыватель лаборатории С сбоит с 06:12», «экран LF-135 — 74 %»,
  «D-7720 вчера отказался от испытания»).
  - Начальник — NPC на смене: у охраны `shift_chief`, у инженеров `dept_head` или старший техник, у учёных `research_director`,
    у D — конвоир на `postD`.
  - Он подходит к игроку (см. «Лично») или игрок сам идёт к нему: в диалоге кнопка «Наряд на смену».
  - Если игрок не пришёл за 15 игровых минут — по рации: «Волков, зайдите за нарядом».

- **Терминал.** Вкладка «НАРЯДЫ»: предложения (необязательные и плановые) с кнопкой «Взять»; текущие задачи с `TD.brief`; журнал задачи.

## 9. Спецификация КПП «Пропуск» (с «Стоять, документы!» и «Чужая карта»)

**Пять ответов.**
- Делает: стоит у контрольной двери, смотрит человеку в лицо, открывает панель пропуска, жмёт проверки.
- Решения: насколько тщательно проверять при растущей очереди и что сделать с человеком.
- Исходы: успех — без ошибок; частично — ошибки или жалобы; провал — пост брошен или 2+ нарушителя прошли.
- Мир: человек проходит или нет, его работа идёт или срывается, дальше журнал доступа, дела и истории.
- Повтор: десятки комбинаций, ночь и день, три КПП, а NPC-охранники проверяют и самого игрока, если он не охранник.

### 9.1 Комнаты и точки

Трафик измерен, **ФАКТ**: предъявлений карты в игровой час днём — `d.liftBC` 9–12, `d.ab` 7–10, `postD` 0–4.
Проверяется только вход в охраняемую зону — это примерно половина потока, 4–6 человек в час на загруженном КПП:
одна проверка в 10–15 реальных секунд, для телефона плотность хорошая.

|---|---|---|---|---|
| `cpC` КПП «Восток» | `d.liftBC` (liftB ↔ corrC) | `liftB` | `corrC` у двери, рядом пост `postC` | крыло С: камеры LF-123…138, лаборатории |
| `cpB` КПП «Б–А» | `d.ab` (corridor ↔ corrA, x≈−26) | `corridor` | `corrA` у двери, рядом `post` и `postA` | командный центр, серверная, `medA`, МОГ, кабинет директора |

### 9.3 Правила (`TD.cp.verdict(w, cpId, n)`)

Возвращает `{ valid, reasons[], purpose }`. Причины недействительности — от существующих полей:

| Причина | Условие (код) | Видно без базы? |
|---|---|---|
| `no_card` | `!card \|\| card.holder !== n.id` | да: «Карту забыл…» |
| `swap` / `stolen` | `card.owner !== n.id` | только по фото и имени |
| `revoked` | `card.revoked` | только по базе |
| `no_access` | `!checkCard(card, door.reqFrom(side))` без временного допуска | уровень и разрешения на карте |
| `expired_temp` | у задачи нужен `tempUntil`, а `tempUntil < now` | только по базе |
| `off_shift` | `!People.works(n, day) && !(n.overtime > now)` | только по базе |
| `sick` | `n.isSick(now)` | только по базе |
| `restricted` | `n.restricted` и цель — Observation или Containment | только по базе |
| `vetrov` | предмет `vetrov_pass` (EV-1в, G07) | по базе: «карта не выпускалась» |
| `compelled` | у NPC активен эффект horror `compulsion` | ответ на вопрос о цели странный |

Цель визита (`purpose`) берётся из `n.job` (название и комната шага) или из блока расписания. У вора — правдоподобная, но
не по профессии («в серверную, проверить стойку» у повара). У «поручения» — странная («мне надо успеть на заседание»).

### 9.4 Двери и очередь (NPC)

- `World.presentCard(doorId, cardId, who, fromRoom)`. Если `d.cp`, КПП укомплектован (`by` стоит на точке ближе 3,5 м
  или NPC-охранник `arrived`), `fromRoom === side`, `who !== by` и человек ещё не пропущен (`cleared[who] > now` нет) —
  вернуть `R.Check`. Результат не идёт в журнал как отказ.
  - После «пропустить» — обычная проверка карты: `Granted` или отказ замка.
  - После «отказать» — `R.DGuard` на 30 игровых минут.
- `brain.handleDoor`. `R.Check` → `'Wait'`, один раз реплика «Сейчас, пропуск…». Ворота у дверей из кода толпы сами выстраивают очередь.
  - Терпение = 6 + 4 × diligence игровых минут, у спешащих (приоритет задачи ≥ 4) — половина.
  - Терпение кончилось: жалоба по рации («Пост «Восток» держит нас десять минут»), отношения −3, а дальше:
    - если есть другой путь (`planPath` с повышенной стоимостью этой двери) — уйти им;
    - иначе `job.blockedUntil = now + 30`, работа задерживается.
- `canPlanThrough`. Укомплектованная дверь КПП считается проходимой для всех: решает охранник.
  Когда КПП занимают или освобождают, `lockEpoch++`.
- Человек без карты может подойти к КПП только пока там кто-то стоит. Иначе он, как сейчас, сообщает о потере, и SCP LIFE перевыпускает карту.

### 9.6 Поток игрока (`game.js`)

1. Подсказка `promptFor`. NPC с `R.Check` на КПП игрока → «Проверить документы: Д-р Ким».
   Любой NPC при активном `doc_check`, или охранник рядом с человеком без карты либо вне блока → «Стоять! Документы».
2. ИСПОЛЬЗ. открывает **нижнюю панель «ПРОПУСК»**. Это половина экрана, игра идёт, очередь растёт.
   - На панели:
     - строка карты: ФИО, должность, `L` и разрешения, «временный допуск до …», номер карты;
     - **фото** — приметы владельца карты из `S.looks(card.owner)`: «мужчина, ~45, седые, коротко, борода, очки».
       Приметы *предъявителя* не показываются: игрок смотрит на человека сам.
   - Кнопки проверок, каждая стоит времени:
     - «Сверить с базой» — удержание 1,5 с: статус аннулирования, на смене ли, больничный, отстранение, временный допуск, «не выпускалась»;
     - «Цель визита» — реплика NPC.
   - Кнопки решения: «Пропустить», «Отказать», «Задержать», «Вызвать офицера», «Проводить».
   - Клавиши 1–5 на ПК; кнопки не меньше 48 px.
3. Решение уходит в `w.playerAct('checkpoint', { npc, decision, checks })`. Короткий итог — в ленте («Ким прошёл»),
   строка — в журнал задачи. Правильность игроку не сообщают: она проявится последствиями.
4. «Стоять!» (`act:stop`): `n.heldUntil = now + 2`; в `brain.decide` это план `Confined` «Остановлен охраной», `agent.clear()`.
   Дальше — та же панель.
   - «Пройдёмте» (`escort_staff` в `detHall` / `postX`): NPC идёт следом, `escortedBy = 'player'`.
   - «Вызвать подмогу»: Директор назначает ближайшего охранника или офицера, тот идёт сам.
   - «Закрыть проход»: `door.restricted = true` на 30 минут у ближайшей Security-двери, `lockEpoch++`; запись в журнал решений,
     начальник смены оценивает обоснованность.
5. **Игрок-не охранник у КПП, где стоит NPC-охранник.**
   - `presentCard('player')` → `R.Check`, реплика «Пропуск, пожалуйста».
   - NPC-охранник оценивает `verdict` по карте, которую выбрал игрок.
   - С чужой подобранной картой игрока могут задержать. Это закрывает лазейку «подобрал карту — прошёл куда угодно».

### 9.7 Поведение NPC

- **Посты.** `assignPosts` (scplife.js:612) распределяет охранников на КПП в часы пик. NPC-охранник выполняет `pass_control`:
  - очевидные случаи (`no_card`, `no_access`) обрабатывает всегда;
  - тонкие (`swap`, `revoked`, `expired_temp`, `off_shift`) — с вероятностью `0.55 + 0.4 × diligence × focus`;
  - «Сверить с базой» делает с вероятностью diligence. Промахи записываются в `w.td.breaches` с его id.
- **Особые случаи на смену игрока.** Директор старается дать 1–2 за дежурство: сначала из реального состояния, если нет —
  создаёт **обычную человеческую ошибку** настоящим изменением мира через `w.rng`:
  - соседи по общей койке путают карты — меняются `holder`;
  - у NPC с задачей за КПП истекает временный допуск (`tempUntil = now + 1`);
  - NPC оставляет карту на койке (`card.holder = null; card.room = bedRoom`).
  - Аномальные случаи (Ветров, «поручение») — только при реальном состоянии объекта, Директор их не выдумывает.
- **Вор** (EV-1б, редко, не чаще раза в двое суток). NPC: 2+ замечания, стресс выше 60, `griefUntil > now`, diligence ниже 0,5.
  Он находит карту (`Dirt.remove`) и не сдаёт её. Получает задание `misuse_card`: путь в `armory` через КПП `cpB`, на месте
  `arms.armory.pistol--`, у NPC `items: ['pistol']`. Оружие не применяет: страх, «для себя».
  `access_audit` оружейника ловит его по журналу, открывается дело `C… «Недостача в оружейной»`.

### 9.8 Последствия

| Решение | Верно, если | Последствия верного | Последствия неверного |
|---|---|---|---|
| Пропустить | `verdict.valid` | работа NPC идёт; задача быстрее | нарушитель прошёл → `w.td.breaches`; `access_audit` (`security_officer`) и `accessAudit` → замечание игроку с причиной; дальше по ветке: недостача, `ins`+2 у LF-121, поручение LF-126 выполнено |
| Отказать | `!valid` | репутация +2; аномалии +4 и улика по делу; украденная карта возвращается владельцу (`holder`) — его отношение +8 | отношение NPC −8; `job.blockedUntil`, задача задерживается; жалоба `TD.complaint`; 2 жалобы за смену → замечание |
| Задержать | вор, «Ветров» с отказом сдать пропуск, D вне блока | `detain` (jobs.js:74) → `det1–3`; дело | тяжёлая жалоба: −12 и замечание |
| Офицер | всегда безопасно | NPC-офицер приходит, решает по своему навыку; кредита игроку нет | — |
| Проводить | валидная цель без допуска | работа NPC идёт; КПП пустеет — очередь растёт | — |

### 9.9 Сохранение и производительность

- **Сохранение:** `w.td.cp` (кто стоит, пропущенные и отказанные с таймерами, проверки), `w.td.breaches`, `w.td.complaints`.
  Перепутанные карты сохраняются в `cards`. Новые поля NPC (`cpWait`, `heldUntil`, `items`) — через `Npc.EXTRA`.
- **Производительность:** одна проверка `d.cp` в `presentCard` (вызывается редко); никакой работы за кадр.
  Панель — заранее созданный DOM, меняется только текст.

## 11. Спецификация «Ремонт»

**Пять ответов.**
- Делает: осматривает, меряет, читает журнал, выбирает причину, берёт деталь на складе, отключает автомат, чинит в мини-механике, проверяет.
- Решения: способ диагностики, причина, отключать ли питание, ждать ли охрану.
- Исходы: исправлено; повторный отказ позже; удар током, темнота у соседей, замечание.
- Мир: свет, двери, камеры, датчики, экран; запасы склада; повторные отказы и дела.
- Повтор: 10 видов × 3–4 причины × место (опасность, темнота, очередь).

### 11.2 Шаги (`jobs.js`, вид `fix`)

| # | Шаг | `need` | Где | Что делает |
|---|---|---|---|---|
| 0 | Дождаться охрану (если `danger`) | `wait:escort` / `act:alone` | у входа в зону | `requestEscort` → `stand_guard` охраннику |

Исход:
- **Успех:** причина угадана.
- **Частично:** причина не та. Симптом снят (`fix` вызывается), но `f.relapseAt = now + w.rng.range(30, 120)`.
  В 30 % случаев проверка сразу не проходит, и можно сразу поставить диагноз заново.
- **Провал:** срок истёк или ушёл, не закончив.

Повторный отказ (`TD.fix.relapse`) создаёт новую неисправность того же вида в той же комнате с `relapseOf`.

### 11.3 Мини-механики (телефон, `game.js` + `index.html` `#mini`)

Общее: нижняя панель, большие кнопки, никаких перетаскиваний (только нажатие и одно удержание), мышью тоже удобно.
Интерфейс только собирает ввод — результат считает симуляция: `w.playerAct('breaker', { panel, id })` и т. п.
Тесты вызывают те же функции.

- **M1 «Щиток».** Сетка из 8–12 автоматов с подписями комнат цепи щитка (`room.circuit` из `infra.circuitOf`).
  Нужно отключить автомат комнаты ремонта. Неверный выбор — реальное отключение чужой комнаты на 3 игровые минуты
  (`plannedOutage`): люди реагируют, у horror есть объяснение `outage`.
  В режиме EV-3 — ограничение мощности: включить можно 3 цепи из 5.
- **M2 «Разводка».** 4 цветных провода, порядок напечатан в «СЕРВИСНОМ ЖУРНАЛЕ» инженерного терминала (`infra.log` + схема двери).
  Игрок нажимает цвета по порядку. 2 ошибки — искра (`shock`, если не было блокировки) и испорченный модуль.
- **M3 «Калибровка».** Стрелка движется по режиму датчика:
  - `drift` — медленно ползёт;
  - `spike` — прыгает;
  - `stuck` — стоит на месте.
  Удерживать «ТОНКАЯ НАСТРОЙКА», чтобы держать стрелку в зелёной зоне 3 с. При `stuck` стрелка не движется вообще —
  игрок должен понять, что датчик надо менять. Это диагноз через устройство.
- **M4 «Замер».** Три точки замера (A, B, C); нажатие показывает число; одно значение вне нормы. Используется в шаге 1 и в обходе щитков.

Стрелка — CSS `transform` у заранее созданного элемента, обновляется только при смене значения. Никаких выделений памяти за кадр.

### 11.4 Опасная зона и сопровождение

- `danger = true`, если место ремонта:
  - типа `Containment`;
  - наблюдательный пункт объекта с `threat >= 45` или с `temper` из `aggressive`, `predator`, `shy-predator`;
  - на уровне −9;
  - или это служебный лифт ночью — SCP-LF-122, одному нельзя (`alone_only`).
- Шаг 0: `requestEscort` (scplife.js) назначает `stand_guard` охраннику. Шаг ждёт `guardIn(site)` (brain.js:293; в `director.js` нужна копия функции).
- `act:alone` («Идти без охраны»): `t.violation = 'без сопровождения'`.
  - Если камера видела, после задания — замечание с вероятностью 0,6 (`camReview`).
  - Риск реакции объекта:
    - L-001 — нерегулярный посетитель, `tm.d += 9`;
    - LF-143 бросается к стеклу;
    - LF-141 перестаёт двигаться под взглядом, стоит пустить взгляд в сторону — двигается;
    - ночной лифт уходит на этаж «—».
- B2: игрок получает временный допуск на время задания.
- Охраннику-игроку достаётся зеркальная ситуация G14: принять просьбу, прийти, стоять рядом. Ушёл — NPC-техник прекращает работу.

### 11.5 Поведение NPC

- NPC-техники выполняют `fix` сами:
  - диагноз верен с вероятностью `0.5 + 0.45 × diligence × focus`, +0,1 при `tasksDone > 20`;
  - **физически** ходят на склад за деталью;
  - блокировку делают через `plannedOutage`;
  - бывают повторные отказы с их именем в журнале — и сплетни через память;
  - страх и запрос охраны работают, как сейчас (Гуров).
- Электрикам меньше бессмысленных `power_check`: износ генератора растёт, и проверка нужна, только когда его стоит проверить (износ ≥ 30).

### 11.6 Сохранение и производительность

- Поля неисправности хранятся в `infra.save` → `faults`. `w.td.stock` и `p.items` — как в §10.7.
- Нагрузки нет: события дискретные, мини-механики живут в DOM вне игрового цикла.

## 12. M2: короткие спецификации

### 12.1 «Протокол испытания» (учёный)

- **Данные.** Протокол хранится в `w.td.protocols`:
  ```js
  { id, by, scp, hyp: { id, prop|null, text }, exp, equip: [], party: { dclass, staff: [] },
    status: 'draft'|'submitted'|'approved'|'setup'|'running'|'analysis'|'done'|'aborted',
    marks: [{ at, seen }], quality, danger: { at, seen, aborted }, conclusion, correct }
  ```
- Каждому эксперименту в `def.exps` добавить декларативные поля:
  - `tests: ['prop_id']` — какие свойства опыт может подтвердить (сейчас это спрятано в `experiment()`);
  - `needs: ['em_sensor', 'recorder', …]`;
  - `risk: 0–2`.
  Это данные для ≈85 опытов у 28 объектов, около дня работы.
- **Ложные гипотезы.** По 2–3 на тип объекта (`kind` / `temper`): «реагирует на звук», «зависит от температуры», «действует только через камеры».
- **Шаги:**
  1. `study` (`act:study` у Desk или Console в `archiveA` / `archiveS` / `officesC`): каждый просмотренный источник даёт улику.
     Источники — досье, `a.experiments`, журнал датчиков, `a.journal`.
  2. `act:hypothesis`: выбор из трёх вариантов (скрытые свойства и одна ложная гипотеза). Методы, чьи `tests` связаны
     с гипотезой, подсвечиваются только после двух изученных источников.
  3. `request` (уже есть): этика, утверждение, D-класс. Синхронизация: эксперимент ждёт `wait:dclass_in_room`.
  4. `equip`: взять комплект в `labC` / `lab` / `lab2` (`take:`) → установить у пульта (`act:install`). Без нужного комплекта качество ×0,5.
  5. `run` (`act:run`): три метки на 25 / 55 / 85 % длительности. Объект делает характерное движение и даёт всплеск датчика на 1,5 игровой минуты.
     Метка засчитана, если `p.gazeAt === scp` или камера камеры открыта в терминале (`w.camWatch`).
     При `risk` появляется признак опасности со «окном» на прерывание (`act:abort`): данные частичные, вреда нет.
  6. `conclude` (`act:conclude`):
     - свойство реально и данных ≥ 0,5: «подтверждена» → `a.reveal` (правила, события, знание);
     - гипотеза ложная: «опровергнута» → знание +3, репутация +;
     - «подтверждена» для ложной → `a.falseNotes`: позже другой опыт противоречит записи → дело «ошибка в досье», репутация −;
     - «недостаточно данных» безопасно и даёт мало.
- **NPC.** Учёные проходят тот же протокол с ошибками по `curiosity`, `diligence` и `focus`. Их ложные записи игрок может найти и опровергнуть.

### 12.2 «Барак» (класс D)

- **Данные.**
  - Предметы у игрока и NPC: `bread`, `cig`, `soap`, `letter`, `choc`, `pills`.
  - `w.player.dstanding` от −100 до 100 — уважение среди D (отдельно от `rep.dclass`, расположения охраны).
  - `w.td.block[hall] = { discontent, petition, strike, riot }`.
- **Задания:**
  - D1 поверка (`roll_call`: `wait:time` + `stay:3` у точки строя или койки);
  - D2 пайка (`ration`: очередь в `w.queues` у `FoodCounter`, тот же код, что у NPC → `bread`);

- **EV-5** — см. §6.
- **NPC.** У NPC-D те же нужды и предметы. Ссоры уже есть (`EV.Conflict`), добавляется только эскалация до драки при высокой вспыльчивости.

## 13. M3: медик, МОГ, диспетчер, руководители (как их кормит Наряд)

- **Медик.**
  - Ситуации: первая помощь (`medkit`, `S.Med.firstAid`), сортировка нескольких раненых (порядок), транспорт, операции, медосмотры после воздействий.
  - Решения: кого первым, отстранить ли сотрудника (`restricted`, он потом встречается на КПП).
- **МОГ.**
  - Ситуации: приём поступления (`arrivalTick`), сопровождение объекта, повторное содержание с протоколом счёта, учения с настоящим маршрутом.
  - Решения — тактика и ROE (arms.js).
- **Диспетчер.** Играет «руками» Наряда: видит входящие ситуации и вручную назначает исполнителя из тех, кто на смене.
  Вызов идёт по рации NPC, тот идёт сам. Ложные вызовы LF-135 (EV-4) — его главная загадка.
- **Руководители.** Уже есть повестка, бюджет, этика. Добавляется приказ из терминала: начальник смены ставит NPC на КПП,
  назначает конвой, а в отчёте за смену видит ошибки КПП и повторные отказы.

// node: тот же MODS, что в sim-test; телепорт игрока — инструмент наблюдения, не механика
const w = S.Content.createWorld(3, { prof }); const p = w.player; let idle = 0, busy = 0, last = w.now; const kinds = {};
w.events.listeners.push(e => { if (e.type === 'TaskIssued' && e.actor === 'player') { const t = w.tasks.get(e.target); kinds[t.kind] = (kinds[t.kind] || 0) + 1; } });
const put = (room, pos) => { const r = w.fac.room(room), q = pos || r.center; p.pos = { x: q.x, y: r.floorY, z: q.z }; p.roomId = r.id; };
for (const end = w.now + 450; w.now < end;) { w.tick(0.1); const ts = w.tasks.activeFor('player'); const dm = w.now - last; last = w.now; if (!ts.length) { idle += dm; continue; } busy += dm;
  const t = ts[0], s = t.steps[t.si]; if (!s || (t._w && w.now < t._w)) continue; t._w = w.now + 1; const poi = s.poi ? w.fac.poi(s.poi) : null; put(s.room, s.pos || (poi && poi.pos));
  const n = s.need || 'hold';
  if (n === 'hold') w.playerStepDone(t); else if (/^cams:/.test(n)) w.cams.slice(0, 8).forEach(c => w.viewedCamera(c.id));

  else if (/^terminal:/.test(n)) w.playerTerminal(n.split(':')[1]); else if (n === 'experiment') w.playerExperiment(s.scp, s.exp);
  else if (/^interview:/.test(n)) w.interview(n.split(':')[1]);
  else if (/^act:/.test(n)) w.playerAct(n.slice(4), S.TaskDirector.autoArgs(w, t, s));   // autoArgs: тестовый «разумный» выбор
}
console.log(prof, 'idle', Math.round(idle / (idle + busy) * 100) + '%', kinds);

## 15. Риски и открытые вопросы

- **Плотность КПП** (**ПРЕДПОЛОЖЕНИЕ**). 4–6 проверок в игровой час на `cpC` — это одна в 10–15 реальных секунд.
  Если окажется утомительно, уменьшить долю проверяемых — например, только тех, кто идёт в зону камер — или ставить КПП только в часы пик.
- **Фото** должно точно совпадать с моделью. Если `S.looks` разойдётся с `humans.js`, механика станет нечестной.
  Нужен тест: `S.looks(n)` совпадает с `Humans.spec(n)` по 300 NPC (запускается в `browser-smoke`).
- **Конфликт с другими агентами.** Ведущий развивает `director.js` (v1), другой агент снимает толпу (`brain.js`, `people.js`, `world.js`).
  Этот проект **расширяет** v1 и не переименовывает `S.TaskDirector`. Всё, что меняет темп NPC, согласовать с работой по толпе.
- **Объём данных M2:** поля `tests` / `needs` / `risk` для ≈85 опытов. Можно начать с 8 объектов, у которых больше всего скрытых
  свойств (T-2 и L-001), а остальным оставить старый поток.
- **Баланс жалоб и замечаний.** Пороги (2 жалобы → замечание) проверить в игре: охранник не должен бояться отказывать.
- **Нагрузка на телефон.** Новых per-frame циклов нет; `Approach` даёт не больше одного NPC; Директор тикает раз в 2 с.
  Проверить в `browser-smoke` с `ROOMS`.
